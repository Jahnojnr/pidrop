# Security, privacy and operational requirements

Draft for security and Nigerian legal review; no compliance or certification claimed.

- **Identity/session:** server-managed phone OTP challenges, anti-enumeration responses, rate limits per identity/device/IP and abuse monitoring. Short-lived access tokens, refresh rotation/revocation and device/session management are design requirements; resolve exact TTLs. Android secrets in platform-protected storage/Android Keystore where appropriate; never in plain preferences, logs or backups. Admin authentication requires MFA and secure session management; step-up for high-risk actions.
- **Authorization:** enforce tenant/role/ownership on every API call and realtime subscription, not merely hidden UI. Staff roles scoped to support, finance, verification, ops and audit. Log privileged access to sensitive records; separate duties for sensitive settlement/refund actions where approved.
- **Transport/storage:** HTTPS, encrypted storage and backups, secrets manager, least-privilege service accounts, environment separation and key rotation. Never commit API secrets, private keys, signed document URLs or real test data. Android Maps keys must be restricted, not treated as secret.
- **Location:** request Android runtime permission just in time, explain purpose and permit manual address entry. Background location only with a separately justified approved use and platform policy compliance. Accept location updates only from an assigned rider during an authorized active delivery, and expose only to authorized parties within approved time window. Validate timestamps/rates and stop access on completion/unassignment. Precision, retention and sharing with recipients are unresolved.
- **Sensitive data:** private document upload/download, malware/content checks, short-lived authorized access, encryption, data minimization and access audits. No PIN/OTP, document image, bearer token or full provider callback in analytics/logs. Protect screenshots/clipboard where risk justifies it without impairing accessibility.
- **Payments and custody:** provider verification server-side, signed webhook validation, idempotent mutations, financial reconciliation, immutable audit. Delivery PIN is separate from pickup proof and payment. Do not collect/store raw card data unless provider and compliance architecture explicitly permits it.
- **Privacy governance:** counsel to decide lawful basis, consent, NDPA/NDPC applicability, notices, processors, international transfers, retention/deletion, DSAR, incident notification and legal holds. Provide deletion/export/support workflows as policy requires; do not claim a finalized retention period.
- **Abuse/reliability:** throttle OTP, PIN and location endpoints, lockout/recovery policy subject to review, protect against fraud and replay; plan monitoring, incident response, backups/restores, disaster recovery, vulnerability management and dependency scanning. Never expose operational diagnostics to customers.

Acceptance: negative authorization tests for every actor and object, session revoke/rotation and replay tests, logs inspected for secrets/PII, verified private object isolation, location-scope/revocation tests, security review and documented policy approvals before pilot.
